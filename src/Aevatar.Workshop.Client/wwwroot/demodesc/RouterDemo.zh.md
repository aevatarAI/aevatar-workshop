# 路由演示

本演示展示了一个强大的工作流，其中 **路由 Agent** 在两个专门的 AI Agent（**研究员**和**作家**）之间进行智能协调，以完成一个多步骤的任务。它演示了如何将一个复杂的过程分解并适时地委派给正确的 Agent。

### 工作流：从任务到报告

您只需单击一下即可启动整个过程，该过程将按照精确、受管理的时序展开：

1.  **任务启动**：当您运行演示时，系统会创建一个 `BeginTaskGEvent`，其初始目标为：`"研究 AI agent 并撰写一份关于它的简短报告。"` 此事件不会发送到某个特定的 Agent，而是发送到中央的 **路由 Agent**。

2.  **智能路由（第一步）**：路由 Agent 分析任务描述。它确定第一个逻辑步骤是"研究"，并通过创建 `ResearchEvent` 事件并将其发送给相应的专家——**研究员 Agent**——来自动路由任务。

3.  **研究员的角色**：研究员 Agent 在收到 `ResearchEvent` 后激活。它的工作是执行任务的研究部分，遵循其在 `ResearchPromptTemplate.cs` 中简单而专注的提示：
    > 你是一个研究员，你只需要根据研究内容完成研究并输出研究结果。

4.  **传递接力棒**：研究完成后，研究员 Agent 会将其发现发布在一个 `RouteNextGEvent` 事件中。这向路由 Agent 发出信号，表示第一步已完成，结果已准备就绪。

5.  **智能路由（第二步）**：路由 Agent 得知研究已经完成，便进入下一个逻辑步骤："写作"。它创建一个 `WriteEvent` 事件，用研究结果填充它，并将其发送给 **作家 Agent**。

6.  **作家的角色**：作家 Agent 激活。它接收来自 `WriteEvent` 的内容，并使用其在 `WriterPromptTemplate.cs` 中的专用提示来生成最终输出：
    > 你是一个作家，你需要根据所提供的内容输出文章。

您可以在"AI 消息"面板中观察这整个事件链，包括发送给每个 Agent 的提示及其最终输出。这演示了一个松散耦合但高效的多 Agent 系统，由一个中央路由器进行编排。

- 演示由 AI 驱动的路由和多代理编排。
- 在运行之前，您必须在 `src/Aevatar.Workshop.Host/appsettings.json` 中配置您的 API 密钥。
- 在运行演示之前选择 LLM 系统。
- 主机日志显示编排详情，客户端日志显示最终报告。
- 非常适合探索由 AI 驱动的代理工作流。
